## いまあるもの（MVP）

- リポジトリ内 JSON（`public/data/questions.json`）から出題
- 4択 → 正誤表示 → 解説 → 次へ
- 終了時の簡易正答数
- データ取得は `QuestionRepository` 経由（差し替え前提）
- Sheets 同期スクリプトはスタブ（`scripts/sync-questions.mjs`）

## 公開・運用

### GitHub Pages で公開する

静的ビルド（`npm run build`）を Pages で配信する。

- **前提**: 特になし（`base: './'` は設定済み）
- **メモ**: リポジトリは作成済み（`70nanon/ai-passport-quiz`）
- [x] 完了（PR: https://github.com/70nanon/ai-passport-quiz/pull/1）

### 本番の問題データを投入する

スプレッドシート上の問題を JSON スキーマに合わせて入れる。

- **前提**: シート列をアプリのスキーマに対応させる  
  （`id` / `category` / `question` / 選択肢 / `answer` / `explanation`）
- **メモ**: UI 変更なしでデータ差し替えだけでよい

---

## 問題データの取り方（Repository 差し替え）

### スプレッドシート → JSON 同期スクリプトを実装する

`npm run sync:questions` で Sheets（公開 CSV など）から `questions.json` を生成する。

- **前提**: シートの列定義が固まっていること、取得手段（公開 CSV URL など）が決まっていること
- **関連**: [`scripts/sync-questions.mjs`](../scripts/sync-questions.mjs)

### ビルド／CI で同期してからデプロイする

GitHub Actions などで「同期 → ビルド → Pages デプロイ」を自動化する。

- **前提**: 上記の同期スクリプト、Pages 公開

### 実行時に公開シート／CSV を読みにいく

アプリ起動時にネット上のデータを `fetch` する Repository 実装を追加する。

- **前提**: シートまたは CSV をウェブ公開できること
- **メモ**: 認証付き Sheets API より、公開 CSV／Apps Script の方が Pages 向きで簡単

### DB / API から問題を取得する

バックエンドや BaaS の API を叩く Repository を追加する。

- **前提**: API の用意、（必要なら）ホスティング。静的 Pages だけだと CORS／認証の設計が必要
- **メモ**: UI は `QuestionRepository` のまま差し替え可能

## 出題・学習体験

### 分野（category）で絞って出題する

`category` を使ったフィルタやモード選択。

- **前提**: 問題データに `category` が入っていること（スキーマには既にある）

### 苦手分野・間違えた問題の復習

不正解だった問題や分野をあとで優先して出す。

- **前提**: 安定した `id`（スキーマに既にある）、回答結果の保存（下記「学習履歴」）

### 学習履歴を端末に残す

正誤・解いた日時などを `localStorage` などに保存する。

- **前提**: 特になし（ログイン不要で始められる）
- **メモ**: ブラウザや端末を変えると消える／共有されない

### アカウント連携で履歴をクラウド保存する

ログインして複数端末で進捗を共有する。

- **前提**: 認証基盤と保存先（DB / BaaS など）、学習履歴のモデル設計
- **メモ**: 端末ローカル履歴より規模が大きい

### 出題モードのバリエーション

例: 全問固定順、ランダム、制限時間、本番形式（解説は最後にまとめて見せる）など。

- **前提**: 基本のクイズフローがあること（MVP で充足）
- **メモ**: モードごとに「いつ解説を出すか」が変わる点に注意

### ブックマーク／後で解く

気になる問題を印つけて一覧から再開する。

- **前提**: `id`、端末またはクラウドへの保存

### 解説や問題文の見やすさ向上

長文・箇条書き・リンク・画像付き解説など。

- **前提**: データの持ち方（Markdown にするか、画像 URL を持つか）を決める
- **メモ**: スキーマ拡張が必要になることが多い

## メモ（構成の指針）

- 問題の置き場を変えるときは、できるだけ **新しい `QuestionRepository` 実装を足す**方向にする
- 学習系機能は **`id` / `category` をキー**にすると後から足しやすい
- 「更新の手間を減らす」本命は、シートを正本にして **同期 or 実行時取得** に移すこと
